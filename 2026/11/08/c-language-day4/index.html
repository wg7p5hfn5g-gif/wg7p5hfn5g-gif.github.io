四、文件读写：让数据留下来

之前所有程序一关，数据全没了。文件操作让数据可以存到硬盘。

打开与关闭

三种常用打开模式

模式 含义 文件不存在时 已有内容
"r" 只读 打开失败返回 NULL 保留
"w" 只写 自动创建 清空重写
"a" 追加写 自动创建 保留，写在末尾

⚠️ 坑 1："w" 会清空原文件！只是查看就用 "r"，追加内容用 "a"，别手快把重要文件清掉。

五、实战：学生成绩管理

把结构体、数组、文件读写串起来——录入成绩、算平均分、存到文件、再读回来显示。

运行一遍，目录下会多出一个 scores.txt，里面就是刚录入的数据。数据第一次活过了程序的生命周期，这个感觉挺妙的。

六、今天的坑

  1. "w" 模式会清空文件，查数据要用 "r"，追加用 "a"
  2. **fopen 之后必须判 NULL**，尤其读文件时文件可能不存在
  3. fscanf 读 int/float 要加 &，读字符串数组不用加
  4. **用完一定要 fclose**，否则数据可能没真正落盘
  5. 结构体传参尽量传地址（const Student *p），避免复制整个结构体
  6. -> 用于指针，. 用于变量，写混了编译就报错

七、小结

今天最核心的一句话：结构体解决「数据怎么组织」，文件解决「数据怎么留住」。

  • 结构体把不同类型的数据打包成一个整体，靠 . 访问成员
  • 结构体数组 + for 循环 = 管理类程序的骨架
  • 指针访问结构体用 ->
  • 文件三件套：fopen → 读写 → fclose，模式选对很关键

回头看，第一天写的 Hello World 到今天的成绩管理，代码量翻了十倍，但用到的还是那几个东西：变量、循环、判断、数组、函数、指针。所谓新知识，多半是旧知识的重新组合。

八、明天计划

  • 学动态内存 malloc / free，让数组长度可以运行时决定
  • 把成绩管理升级成「菜单版」：能反复选择录入 / 查询 / 退出
  • 试试按成绩排序（冒泡排序）

第四天结束，已经能写出有点实用价值的小程序了 🔧

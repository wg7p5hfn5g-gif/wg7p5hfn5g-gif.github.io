渗透学习笔记 · 第八天：XSS 跨站脚本（DVWA）

昨天把 SQL 注入打穿了，今天学 XSS——它和 SQL 注入是同一个祖宗：「数据被当成了代码」，只不过昨天被当成代码的是 SQL，今天被当成代码的是 JavaScript。
红线不变：一切操作只在 127.0.0.1 本地 DVWA 靶场进行。

一、XSS 是什么

网站把用户输入的内容原样输出到 HTML 页面里时，你提交一段 JavaScript 代码，它就会在其他访问者的浏览器里执行。

对比一下：

SQL 注入 XSS
用户输入被当成 SQL 语句 JS 代码
受害者 数据库 浏览器里的用户
能偷什么 库表数据 Cookie、页面内容、按键

二、三种类型

类型 代码存在哪 触发方式
反射型 只在本次请求里 骗人点带恶意参数的链接，点一次中一次
存储型 存进了数据库（如留言板） 每个打开页面的人都会中，危害最大
DOM 型 纯前端 JS 处理 URL 参数 不经过服务器，抓包看不到

五、DOM 型（认识一下）

DVWA 里的 DOM 型藏在 URL 的 # 后面的参数里，特征是：

  • 请求里看不到恶意代码（# 后的内容不发给服务器）
  • 页面自己的 JS 把这段内容写进了 HTML

抓包工具抓不到它，只能靠审计前端代码。今天先记住概念，面试常考三种的区别。

< 变成 &lt;、> 变成 &gt;，浏览器就只当它是文字，不再是标签。配合的纵深防御：

措施 作用
htmlspecialchars 输出转义 最核心，HTML 上下文够用
HttpOnly Cookie JS 读不到 Cookie，偷了 Session 也用不了
CSP（内容安全策略） 响应头限制谁有权执行脚本
前端框架自动转义 Vue/React 默认帮你转义，别用 v-html/dangerouslySetInnerHTML 接用户输入

七、今天的坑

坑 说明
绕不过 Medium 等级 不是你错了，<script> 被过滤了，学过滤器绕过是后面的课，今天只打 Low
存储型弹窗关不完 留言板存了 alert 之后每次刷新都弹，去 MySQL 里删 guestbook 记录或重置数据库
只会 alert 不会延伸 alert 只是验证，多试 document.cookie、document.location 感受「能拿到什么」
分不清三种类型 记口诀：反射型找链接、存储型找数据库、DOM 型找前端 JS
对真实网站测试 违法，同昨天，只有 127.0.0.1

八、小结与明天计划

今天收获：XSS 三种类型 + 反射/存储 Low 打通 + Cookie 窃取原理 + 输出编码防御。和昨天的 SQL 注入连起来看，你已经见过「注入家族」的两个头号成员了，防御思路也是同一个哲学：永远不让用户输入越过「数据」和「代码」的边界。

明天计划：文件上传漏洞——DVWA File Upload Low，讲清「一句话木马」是什么、中国菜刀/蚁剑怎么连（原理层面），以及为什么上传目录不能给执行权限。

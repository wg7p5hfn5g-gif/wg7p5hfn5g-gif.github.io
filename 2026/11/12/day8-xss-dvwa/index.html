渗透学习笔记 · 第八天：我终于搞懂了 XSS

渗透学习第三天，今天轮到 XSS。记录人：我自己。
老规矩：所有操作只在本地 DVWA（127.0.0.1）里做，线上的东西一个字节都不碰。

一、一开始我有点懵：这不就是 SQL 注入换个马甲？

昨天我刚把 SQL 注入四步法打穿，今天学 XSS 的本质和它是一个祖宗——「数据被当成了代码」。我一开始没转过弯：昨天输入被当成了 SQL，今天被当成了什么？

答案是 JavaScript。自己画了个对比表才真懂：

SQL 注入 XSS
我的输入被当成 SQL 语句 JS 代码
谁遭殃 数据库 打开网页的其他人
能偷什么 库表数据 Cookie、页面内容

最大的区别是受害者：SQL 注入是我自己打服务器，XSS 是坑「之后打开这个页面的人」——所以我不是在攻击服务器，是在构造一个陷阱。这个视角一换，后面的东西就全通了。

三、存储型：这个是真的危险

反射型还得骗人点链接，我觉得不够狠。然后我试了存储型（留言板）：

在 Message 里提交 <script>alert(1)</script>，然后刷新页面——又弹了。

我愣了两秒才反应过来：这段代码被我存进数据库了。不是「我中招」，是每一个打开留言板的人都会中招，包括管理员。反射型是钓鱼，存储型是守株待兔，而且兔子自己会来。

顺便踩了个小坑：我多存了几个 alert 之后，页面每次刷新都疯狂弹窗，关都关不完。最后是进 MySQL 把 guestbook 表的记录删了才安静下来（或者直接用 DVWA 的重置数据库按钮，更省事）。

四、DOM 型：今天只记住了概念

第三种 XSS 的恶意代码藏在 URL 的 # 后面——这部分根本不会发给服务器，所以抓包工具（Burp）看不到，只能靠读前端 JS。

我现在的记法是三句话：

  • 反射型：找链接
  • 存储型：找数据库
  • DOM 型：找前端代码

面试据说爱考这个区别，先背下来，等以后学前端审计再深入。

五、我自己的坑清单（今天真的全踩了一遍）

坑 我的经历
Medium 等级打不动 我顺手试了 Medium，<script> 直接被吞了，还以为自己写错了。后来明白那是过滤器在起作用，绕过是后面的课，今天先只打 Low
存储型弹窗关不完 见第三节，删数据库记录才解决
只会 alert alert 只是敲门砖，要多试 document.cookie、document.location 才知道「到底能拿到什么」
中文输入法老毛病 又来了！和写 C 代码那次一样，引号打成了中文的，页面怎么都不弹。写 payload 必须全程英文输入法，这个坑我算是记死了
手痒想碰线上 心里痒过一下，但想到《刑法》285 条和自己昨天写的红线清单，忍住了。靶场只有 127.0.0.1

六、防御：看完漏洞源码，防御代码反而最好懂

Low 的源码就是「原样输出」，所以修复也直白：输出的时候转义。

< 变 &lt;、> 变 &gt;，浏览器拿到后只当是文字，标签就失效了。我把纵深防御整理成四条，贴在了自己的笔记本上：

措施 作用
htmlspecialchars 输出转义 最核心的一招
HttpOnly Cookie JS 读不到 Cookie，就算有 XSS 也偷不走登录态
CSP 响应头 限制谁能执行脚本
前端框架自动转义 Vue/React 默认转义，千万别用 v-html / dangerouslySetInnerHTML 接用户输入

七、今天的总结和明天的计划

把这两天的知识串起来，我发现「注入家族」其实是同一个哲学：

永远不让用户输入越过「数据」和「代码」的边界。
昨天：拼接 SQL 时越界 → SQL 注入 → 修复靠参数化查询
今天：拼接 HTML 时越界 → XSS → 修复靠输出转义

按这个思路，明天要学的文件上传漏洞应该也是家族成员——我猜是「我的文件被当成了可执行代码」？带着这个猜想去打 DVWA File Upload Low，明天验证猜得对不对。

明天计划：文件上传漏洞 + 「一句话木马」到底是什么 + 为什么上传目录不能给执行权限。
